# 변경 요청 가져오기 — 배포 준비

2026-10-16 기준 npm 최신 버전은 `1.5.1`입니다. 이번 기능은 기존 메모 형식 v1/v2를 유지하면서 새로운 입력·검토 흐름을 추가하므로 다음 버전으로 `1.6.0`을 제안합니다. 버전 번호와 실제 게시는 사용자 확인 후 확정합니다.

## 릴리스 설명 초안

자유롭게 적은 지시 사항, 개인 메모, 피드백, 회의록을 HTML 요소별 변경 제안으로 가져올 수 있습니다. 사용자는 원문 근거와 대상을 확인하고, 승인한 항목만 메모로 추가한 뒤 Claude Code나 Codex에 반영을 요청합니다.

- 텍스트 붙여넣기와 UTF-8 TXT·MD·DOCX 가져오기
- 원문 근거·다중 대상·불명확하거나 상충하는 요구 표시
- 요청 편집·대상 재지정·개별 및 일괄 승인·제외
- 승인한 항목만 메모로 전환, 실행 취소·다시 실행·중복 방지
- HTML 또는 원문 변경 시 오래된 분석의 반영 차단
- 기존 Claude Code·Codex 대화를 이용한 분석과 승인 메모 반영
- 한국어 UI의 ‘가져온 요청’, ‘새 요청 가져오기’, ‘임시 저장’, ‘분석 요청 복사’ 안내 개선
- 문서 미리보기 재로드 중 빠른 실행 취소·다시 실행 입력이 빠지지 않도록 키보드 포커스 유지

원문과 검토 기록은 해당 문서 옆 `.htmledit/`에 보관합니다. 전달용·완성본 HTML에는 원문과 미승인 제안을 포함하지 않습니다. 별도 AI API 연결은 필요하지 않습니다.

## 호환성과 업데이트

- Node.js 22.12 이상과 로컬 연결 모드가 필요합니다.
- 편집기와 스킬 런타임을 함께 업데이트해야 새 `requests` 명령을 사용할 수 있습니다. 기존 설치된 스킬은 설치 당시 버전의 런타임을 사용합니다.
- 기존 HTML 메모 형식과 일반 checkout/apply 흐름은 유지합니다.
- 입력 제한은 파일 10MiB·텍스트 20만 자입니다. DOCX는 본문 텍스트만 가져오며, 녹음·PDF·구형 DOC는 지원하지 않습니다.
- Windows 실제 AI 검증과 자동화 검증의 범위는 [검증 기록](CHANGE_REQUESTS_VERIFICATION.md)을 참조합니다. 플랫폼 CI와 각 플랫폼의 실제 AI 사용 검증은 구분합니다.

## 게시 전 마지막 단계

1. 변경 사항을 포함한 최종 커밋에서 Windows·Ubuntu·macOS CI를 확인합니다.
2. 사용자에게 릴리스 버전과 게시 진행을 확인받습니다.
3. 확정된 버전으로 package.json과 lockfile을 함께 변경하고 개발 미리보기 안내를 정식 버전 안내로 바꿉니다. 마지막 후보를 다시 빌드·패키징합니다.
4. 해당 커밋의 검증 후 main에 반영하고 일치하는 버전 태그를 게시합니다. `v*` 태그는 GitHub Actions에서 npm 게시와 GitHub Release 생성을 자동 실행합니다.
5. npm 버전·dist-tag, provenance·서명, registry tarball과 GitHub Release 파일의 해시를 확인합니다. 게시된 패키지를 별도 소비자 폴더에 설치해 스킬과 새 명령을 확인합니다.

현재 준비 단계에서는 package version 변경, 릴리스 태그 생성, npm 게시를 수행하지 않습니다. 기존 원본 문서와 이전 npm 버전은 그대로 유지합니다.
